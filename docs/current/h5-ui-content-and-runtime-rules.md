# H5 UI、前台文案与运行时规则

本文是历史移动端 UI、前台文案、开放世界引导和后台调度器热修记录的当前合并口径。旧日期型修复记录已经归档，不再作为新开发入口。

## H5 页面总原则

- 项目是纵屏优先的 Web H5 游戏，iOS Safari、Android Chrome、PC 浏览器都必须保持可用。
- 游戏页面不是后台面板。地图、战斗、Boss、PVP 的主场景永远优先于日志、卡片、公告和说明。
- PC 端也应保持优化过的纵屏游戏布局，不要拉成横向管理台。
- 移动端核心操作必须靠近拇指区，常用按钮不能藏在滚动后面。
- 文本必须在窄屏下截断、换行或收纳，不能撑破卡片、按钮、徽记或弹窗。

## 前后台恢复与离线规则

- 前后台恢复的 repair 必须由共享触发器统一发起
  （`src/modules/shared/ui/hooks/useForegroundRepairTrigger.ts`），
  地图、战斗、聊天 presence 三条链路共用，不允许各写一套监听。
- **禁止按 UA / 平台分叉主流程**：统一监听 `visibilitychange` / `pageshow` /
  `focus` / `online`，由浏览器决定哪些事件会触发；hook 内部已把同窗口内的
  多个事件合并成一次 repair（默认去重窗口 800ms）。
- `visibilitychange` → `visibility_restore`，`focus` / `pageshow` →
  `foreground_restore`，`online` → `reconnect`，`manual`（手动点「同步」）
  **不占用补齐通道**，不触发刷新帧下发。
- **禁止假在线**：连接断开、重连中、repair 尚未回包时，UI 不得把上一次快照
  留下的列表 / 状态当作实时在线展示。聊天 presence 通过 `presenceStale`
  对外暴露该状态，UI 应显示「同步中」而不是在线人数。
- repair 补齐后若服务端在断连窗口内发生过资产 / 背包 / 进度入库变更，
  必须下发 10302 / 10510 / 12742 刷新帧，**禁止只回 ACK**。
- 刷新帧摘要必须幂等：带递增 `version`，flush 成功后清空 pending，
  连续两次 repair 不得产生重复刷新帧。
- 离线页（`public/offline.html`）必须：不贴边（安全区 + ≥20px 留白）、
  不遮挡、窄屏与 PC 纵屏下均正常、联网恢复后自动重试。

## 战斗页面规则

- 普通战斗、组队战、Boss、PVP 统一走 `UnifiedBattleShell` 和共享战斗页面壳。
- 各模式差异只放在 mode widget、状态卡、技能/丹药面板和提示文案中，不再复制多套页面骨架。
- 移动端底部操作区采用独立 mobile dock，不能依赖 `display: contents + fixed` 这类容易在移动浏览器失稳的组合。
- 核心战斗样式应放在稳定 CSS 文件中，避免把大段页面壳样式重新塞回 `styled-jsx` 运行时注入链。
- Boss / PVP / 普通战斗新增静态页面壳样式时，优先追加到对应 CSS 文件；只有血条宽度、实体坐标、弹字锚点等跟随战斗帧变化的样式才保留为运行时 style。
- 战报、日志、说明卡必须可折叠或可收纳，移动端不能遮挡角色、Boss、技能区和主战场。
- 技能按钮、丹药按钮、撤离/认输按钮必须保持足够点击面积；PC 端也要避免被场景层、日志层或透明覆盖层挡住。
- 战斗丹药、技能和逃跑等动作只有在服务端权威事务成功后才更新资源或战斗结果；失败请求不能先扣库存。
- 发行版战斗 UI 的玩家可见文案必须是游戏内状态描述，不展示服务端、接口、同步、实时房间、ACK、主链、权威状态等实现层词汇。

## 地图页面规则

- 地图主画布、附近实体和核心交互区优先留在移动端首屏内。
- 地图顶部信息、公告、视野/秘境/刷新/退出工具条必须按移动端重新排布，不允许按钮和长地图名挤压变形。
- 地图画布可以按视口高度限制等比收口，但不能改变点击判定、格子坐标或服务端权威移动规则。
- 快速移动体验优化只能改善计划落点、预测、插值和渲染减重，不能绕开服务端移动校验。
- 地图主场景应拆成稳定渲染边界，弹窗、秘境面板、世界情报、成人邀约、暗线来信等状态变化不能拖着主画布反复重渲染。
- 附近 NPC、怪物、道友卡片在窄屏下必须保证名字、称号、说明不越框，并保留横向滑动或收纳能力。

## 角色页与资料展示

- 角色页主信息应聚焦头像、名字、境界、战力和关键状态。
- 名声、气运、双修状态、功法、灵田、炼丹、炼器等历史插件玩法入口都必须是固定核心入口，不再来自插件扩展。
- 属性说明统一使用点击打开、点击空白关闭，不依赖长按作为唯一入口。
- 小型悬浮说明必须避免遮挡主属性区，滚动或窗口尺寸变化时应自动收起。

## 前台文案规则

- 玩家看到的物品、装备、丹药、材料、AI 炼丹、AI 炼器文案必须是玩家视角。
- 前台不展示内部字段、英文技术 ID、JSON、上传路径、服务器裁定、模板限制、概率调试值或生成种子。
- 名称为空或像技术 ID 时，必须生成中文保底名，例如“仙品丹药”“上品灵材”“鸿蒙法宝”。
- 描述为空或含技术噪音时，必须生成简洁中文保底描述。
- 绑定神通、参悟神通、头像、头像框等效果无法解析具体名称时，显示“未命名神通”“未知头像”“未知头像框”等玩家可理解文案。
- 玩家物品接口使用白名单返回，不直接把 `sourceType`、`sourceMeta`、`generatedSeed`、来源实例、来源玩家等内部追踪字段回给前端。

## 装备词条显示

- 装备属性词条颜色只用于帮助玩家理解“该词条在当前境界的大致档位”，不改变物品真实 rarity。
- 武器、法衣、灵冠、步履、法宝按装备 `minRealm` 和属性阈值显示档位色。
- `bind_skill`、`learn_skill` 等技能词条固定显示高价值强调色，不参与普通属性阈值分档。
- 词条颜色规则必须集中在共享显示服务中维护，背包详情和玩家资料装备详情不能各写一套。

## 开放世界引导

- 地图首页的可响应事件、私密邀约、暗线委托、故事链、暗袭弹窗和主目标都必须告诉玩家下一步做什么。
- 引导块至少应尽量包含：是否需要先接受、找谁、去哪、坐标或街区、当前动作说明。
- 任务型邀约在 pending 状态下也应尽量给出目标预览，不要等玩家接受后才第一次知道去向。
- 世界 NPC 因名声、压力或关系拒绝互动时，也要提供返回地图、查看委托或修复关系的明确入口。

## 后台调度与计时器

- 实时连接心跳、房间 tick、AOI watcher、SSE/WS 保活、snapshot flush、运行时缓存 prune 这类短周期基础设施，不强行并入业务调度器。
- 周期结算、周期同步、周期清理、周期巡检等后台业务任务应收口到共享后台调度器。
- 功法点、挂机点、成长点这类长期收益优先使用“时间戳差值 + 显式入口结算”，不要依赖页面停留或常驻定时器不断写库。
- 当前插件体系已退役；历史表只作为迁移期数据来源或兼容账本，不恢复插件定时器链路。

## 维护规则

- 新增 H5 UI 规则、玩家文案规则、装备展示规则或后台调度规则时，优先更新本文。
- 如果某个规则只属于地图、战斗、开放世界或部署专题，也要同步更新对应专题文档。
- 不再新增日期型单点热修 MD；临时排障记录完成后应整合到本文或对应权威专题，再把原记录归档。
