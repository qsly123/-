### 三个最刺眼的事实

1. **每个境界段的防具只有 3 件**（甲 1 + 盔 1 + 鞋 1）。练气玩家全身没有配装决策——
   拿到什么穿什么，这是"单调"最直接的来源。
2. **秘境模板只有 2 个，且分类维度是空的**（这条我一开始判错了，只数了模板条数

   （`fromMajor: 3` 起生效），玩家不加点、不选节点。且 `player_talents` 记录为 **0**。

### 顺带确认的边界（避免瞎编）

- 装备可用属性键共 **11 种**：`boost_atk / def / hp / speed / spiritual_sense /
  armor_penetration / luck / block / skill_damage_bonus / skill_damage_reduction / bind_skill`
  → 扩充装备只能用这些键。
- 丹药可用效果键：`boost_xp`（修为）、`boost_breakthrough`（突破率）、`heal_hp`、`heal_mp`
- 境界 major 共 9 段（练气/筑基/结丹/元婴/化神/炼虚/合体/大乘/渡劫），
  **现有内容只覆盖 1-4，化神及以上完全空白**。
- items 表**无套装/词条字段** → 套装先用命名约定实现，不擅自加字段。

## 二、外部调研结论（可参考的成熟设计）

### 天赋 —— 参考《鬼谷八荒》气运/天赋

- **开局选 3 个天赋**（"鬼谷外门""武圣转世""人族圣体"），有属性阈值与**隐藏联动**
  （选"穿越者"后在特定地点触发专属事件）
- **天赋分阶段解锁**：开局基础天赋 → 筑基期再拿进阶天赋（如"血魔大法"）
- **流派专属天赋**："剑痴"直接强化剑法伤害，形成 Build 感

→ 落到本项目：**天赋要有"选择时刻"**。现有 6 条路径保留为流派骨架，
补"起点天赋 + 进阶天赋 + 流派专属"三层，利用已有的 `key / parent_key / kind` 字段串联，
**不需要新表**。

### 丹药 —— 参考《凡人修仙传》丹药体系

- **九品制**：一品（止血丹、清心丹）基础 → 九品神丹；同品内再分
  **下品/中品/上品/极品**
- **品质直接影响成功率与副作用**：下品筑基丹 +30% 成功且剧痛，中品 +50% 平稳，
  上品 +70% 且附带洗髓
- **按功用分家**：修为类（黄龙丹、金髓丸、聚灵丹、增元丹）、
  突破类（筑基丹/升仙丸）、疗伤解毒（清灵散、养精丹、百草丹）、
  毒药控制（腐心丸、尸虫丸）、辅助类（辟谷丹、定颜丹、饲灵丸）

→ 落到本项目：丹方从 12 扩到 36，**按功用分家**（修为/突破/疗伤/解毒/辅助），
并给丹药引入**下品/中品/上品**三档（复用既有 `base_success_rate`，产出时按档修正）。

### 秘境现状复核（2026-10-18，更正前一版"只有 1 个"的错误结论）

秘境不是"只有 1 个"，也不是单纯按条数算的。代码里（`src/types/game.ts` +
`secret-realm-types.ts`）一共定义了 **5 个分类维度**，库里每个维度都只填了一部分：

| 维度 | 代码定义的取值 | 库里实际 | 缺口 |
|---|---|---|---|
| 现世方式 `spawnType` | `global` 世界 / `personal` 个人 | 只有 `global`×2 | **个人秘境从未现世** |
| 规模 `sizeTier` | `small` 9-13 / `medium` 15-25 / `large` 30-50 | `small`(12×12)、`large`(**80×80**) | **无 medium**；野狼谷还超了 large 上限 |
| 稀有度 `rarity` | common / rare / epic / legendary | `rare`、`legendary` | **无 common / epic**，rare 到 legendary 中间断档 |
| 特殊类型 `specialType` | `wild_wolf_valley`（掌天瓶剧情） | 野狼谷 1 个 | 设计上就只此一种 |
| 生成来源 | `ai` / `fallback` | 全是 `fallback` | **AI 生成一次都没成功过** |

现有 2 个模板：

| 名称 | 规模 | 稀有度 | 尺寸 | 预算 | 怪物 | 首领 | 校验 |
|---|---|---|---|---|---|---|---|
| 野狼谷 | large | legendary | 80×80 | 490 | 28 杂兵 / 6 精英 / 1 首领 | 啸月狼王 | passed=true，阻塞率 0.51 |
| 沉星古域 | small | rare | 12×12 | 130 | 6 杂兵 / 1 精英 / 1 首领 | 幽潮古卫 | **passed=false** |

**顺带查出的既存问题（不是这次改出来的）：**

1. **沉星古域校验不通过** —— `存在 10 个入口无法到达的可通行格`，阻塞率 0.49。
   玩家可能走到一半发现那片区域根本进不去，或者宝箱刷在不可达格上拿不到。
2. **野狼谷 80×80 超出 `large` 定义上限（30-50）** —— 它是掌天瓶剧情的特例，
   但说明规模档位和生成实现已经脱节，后续补 medium 时要先确认走哪套规则。
3. **两个模板 `recommended_realm` 都是 1（练气一层）** —— 野狼谷是 legendary 超大型，
   标成练气可进，难度标注失真。
4. **两个 spawn 都在蓬莱岛** —— 其余 12 张图一张秘境都没有。

→ 因此秘境子任务的目标要改：不是"1 扩到 8"这么简单，
而是**先把分类维度补齐**（medium 规模、common/epic 稀有度、personal 现世、多图分布），
再谈条数。机关/星级房间属于新增玩法，优先级排在补齐维度之后。

   其余 `SECRET_REALM_*` 都没有配置行、走代码默认值。要让它出现，得调触发条件或冷却，不是补数据。

**第一版判断（错的一半）**：我以为 `ensureSmithingCoreSchema` 只建表、不插配方，
于是按「每件装备一条」自己造了 120 条。**结果制造了 120 条重复配方** ——

**仍有 68 件三无**（不可打造、无掉落、不在商铺）。
`scripts/seed-smithing.ts` 已改为**只补没有配方的装备**，补 68 条（每段 17 条）。

最终：配方 120 条（离线包 52 + 补 68），装备可打造 120/120，三无装备 0，悬空引用 0。

**顺带证伪一个假设**（当时怀疑装备/丹药是 LLM 生成、AI 挂了就没得做）：**不是 AI 生成的。**
证据：293 个物品的 `generated_seed` 与 `source_meta` 全为 0，`ai_generation_jobs` 表 0 行。
装备/丹药/配方都来自静态离线包。

但**同类风险确实存在，只是形式不同**：配方是**懒加载落库**的 ——
只有 `ensureSmithingCoreSchema()` / `ensureAlchemyCoreSchema()` 被首次调用时才建表并种入。
若这一步抛错，打造/炼丹页就是一片空白且没有提示。区别是它是确定性的（离线包数据固定），
不像 AI 那样有概率失败，但"从没被触发"这一条就足以让功能看起来是坏的。

**我自己踩的两个误报（记下来，别再犯）：**

1. **丹药效果键误报 24 个**。`boost_xp` 不在 `use` 处理的 `case` 分支里，
   而是在进 switch 前单独 `reduce` 累加修为。只照着 case 列表抄支持键，会把加修为的丹药全判成无效。
2. **炼丹/打造误报失败**。`craftAlchemyRecipe` / `craftSmithingRecipe` 返回的是
   「面板 view」（`getPlayerAlchemyView`），**不是成败结果**。要判断成败得查
   `player_alchemy_logs` / `player_smithing_logs` 里刚写入的那条。

**战斗链已补验证**（`scripts/battle-chain-check.ts`，同一测试号，跑完恢复）：

```
怪物总数 80，有掉落配置 80 只
掉落结构：[{chance:0.62, itemId:"...", minQuantity:1, maxQuantity:2}]

[PASS] 掉落发放 —— 缠雾藤妖 掉落 2 种 → 实际进背包 2 种（青藤芯x1、碎贝壳x1）

```

即「打怪 → 掉材料 → 打造 → 穿上」这条链是通的。

两个顺带确认的事实：
- 掉落表是数组 `[{chance, itemId, minQuantity, maxQuantity}]`，`chance` 是 0-1，
  解析时要兼容 `{items:[...]}` 形态。
- **`equip_slot` 只是回显字段**：前端 `ItemDetailModal` 拿它显示，不参与穿戴逻辑，
  穿戴状态由 `equipped` 布尔决定。库里那条已装备记录 `equip_slot` 是 null（历史遗留），
  按 `item_type` 填不影响功能。

### 物品图标修复纪要（2026-10-18）

玩家反馈「武器没有图标」。查下来是**两个问题叠加**，第二个比第一个严重得多：

**1. 新增物品没写 `icon_url`。** `ItemIcon` 组件在 icon 为空时直接 `return null`
（什么都不渲染），所以玩家看到的是空白而不是占位图。

**2. 库里原有的 icon_url 也全是坏链接。** 存的是
`/uploads/cosmetics/item/four-realms/weapon-sword.png`，但磁盘上根本没有 `/uploads` 这份资源
（curl 一律 404）。真实图标在 `public/worldpack-icons/four-realms/items/`，**只有 12 个文件**。
`rewriteLegacyCosmeticUrl` 只映射了 4 个 ai-smithing 别名，不会把 `/uploads` 改对；
而 ai-smithing 那几个（focus/31263、sword-box、blood-banner、swift-ring）**连本地文件都没有**。

→ 也就是说：**在修之前，全库 293 个物品的图标没有一个能显示**，不只是新加的那些。

修复：不新增图片，把全库图标收敛到磁盘上真实存在的 12 个文件
（`scripts/fix-item-icons.ts`）。分配规则按名称关键字 + id 稳定哈希
（保证同一物品每次刷新拿到同一张图，不会乱跳）：

| 类型 | 图标 |
|---|---|
| weapon | 剑/锋/岚/鸣 → sword；刀/刃/斩/叉 → blade；针/丝/刺 → needle；其余按 id 哈希 |
| armor / shoes | armor-robe（shoes 也只有这一张） |
| helmet | armor-helmet |
| artifact | 盾/甲/钟/塔 → shield；符/幡/旗/环/印 → talisman |
| material | 晶/玉/石/砂/铁/矿 → jade；草/花/露/液/血/魂 → orb |
| consumable | 回血 → pill-red；回蓝 → pill-blue；其余 → pill-bottle |

```
已写入 293 个，仍不可显示 0 个
抽查：weapon-blade/weapon-needle/armor-robe 全部 200
```

**教训**：图标这类"看不见就是没配"的字段，验证时不能只查"是否为空"，
要查**指向的资源是否真的取得到**。空值和坏链接在界面上长得一模一样，
但排查方向完全不同。

### 功法点产出源 + 炼丹炼器缺料弹框（2026-10-18）

**功法点之前根本没有产出源。** 查证：`plugin_gongfa_player_points` 全库只有 1 条玩家记录、
`points > 0` 的是 0 条，代码里只有升级时的**扣减**，没有任何发放；
`RealmRewardAttr` 也只有 hp/mp/atk/def/speed/luck，突破奖励同样不发功法点。
即玩家永远拿不到功法点，功法升级一按就报"功法点不足"。

新增 `grantGongfaPoints()`（写 points + total_earned + plugin_gongfa_point_logs），
挂在突破成功处（`cultivate/route.ts`，`attemptBreakthrough` 只算结果不落库，发放必须放在调用方）：
**小境界 +1，跨大境界 +3**。功法页加了说明"功法点来自突破"。
发放量依据：全库 3 本功法共 9 级，每级消耗 1~3 点；练气到元婴 44 个境界位，够点满还有富余。
这个数值是我定的，想改就改 `GONGFA_POINTS_PER_*_BREAKTHROUGH` 两个常量。

**炼丹/炼器缺料弹框。** 原来材料不够时按钮直接 `disabled`，玩家点了没反应、也不知道去哪弄。
现在按钮可点，点击后弹 `MissingMaterialModal`：列出缺哪些、缺多少，以及每样的获取位置。
来源复用了**已存在的** `item-source-service`（商店 / 怪物掉落 / 任务奖励）+ `/api/game/items/{id}/sources`，
本轮顺手补了第四类：**灵田种植**（种子→产物映射取自离线包 `spiritualFieldSeeds`；
`plugin_spiritual_field_seeds` 要进了灵田页才建表，不能依赖它）。

验证脚本 `scripts/verify-material-sources.ts`：
```
[PASS] 来源覆盖率 71/74（96%）   ← 补灵田前是 69/74（93%）
[PASS] 功法点发放：0 → 1，日志 3 条
```

### 装备实例：阶段系数 + 专精词条 + 炼器专精（2026-10-18）

按需求做了三件事，全部挂在**实例**（`player_inventory` 行）上，`items` 表不动：
新服务 `src/modules/character/services/equipment-instance-service.ts`，
验证脚本 `scripts/verify-equipment-affix.ts`（13 项全 PASS）。

**1. 阶段系数（stage_mult）**
装备基础值在 `items.effects` 里是写死的（按大境界段 × 品质倍率生成），
同一把「筑基凡品剑」在筑基初期和中期打造拿到的一模一样。
现在按玩家**当时的境界**给实例乘一个系数（`player_inventory.stage_mult`），
属性链在 `getPlayersEquipmentBonusMap` 里乘上去。
掉落也生效——挂在通用发放入口 `grantRewardToPlayer` 上（掉落/打造/后台发放都走它）。

**2. 专精词条（affixes）**
`player_inventory.affixes` 这个字段**早就有了，消费端也早就写好了**
（`equipment.provider.ts` 的 `collectAffixBonus`），只是**全项目没有任何写入端**。
这次补上写入：极品（epic）1 条、仙品 2 条、鸿蒙 3 条，**上品及以下一条都没有**；
同一词条仙品数值 > 极品（倍率 1.0 / 1.6 / 2.4）。三类：
- 数值类：属性 flat/percent，随境界放大（现有消费端直接吃）
- 概率类：暴击率 / 格挡率 / 炼丹成功率 / 炼器成功率，不随境界放大（否则后期爆表）
- 技能类：绑定一个技能，复用 `player-active-skills` 的 `bind_skill` 链路

**词条是全池可出，不按流派切分**（2026-10-18 改）。

剑修打的装备体修买了没用，交易所里只能同流派内部流通。
所以改成单一 `AFFIX_POOL`（21 条：9 固定值 + 4 百分比 + 4 概率 + 5 技能器灵），
流派降为**加权不排他**（`AFFIX_PATH_PREFERENCE`，本流派权重 ×2.5，其余照常出）。
实测：剑修同样能掷出格挡率 / 气血 / 防御；本流派 400 次 vs 跨流派 137 次（≈2.9 倍）。

**仙品 / 鸿蒙的出货概率（scripts/verify-rarity-supply.ts）**

### 再修正：怪的数值必须由「装备一身」的玩家反推（第二版也错了）

第二版按裸装成长（×1.117/级）外推怪物，仍然错——**因为装备是指数增长**：

装备属性会乘 `stage_mult = 1.4^(境界-1) / (段倍率×品级种子) × 品级生效倍率`。
实测 25 级化神极品装备（`stage_mult = 257.5`）：

| 装备 | 种子值 | 实际生效 |
|---|---|---|
| 幽冥血刃 atk | 54 | **13908** |
| 幽冥魔铠 hp / def | 272 / 34 | **70053 / 8757** |
| 摄魂幡 atk | 48 | **12362** |

裸装玩家 atk 只有 **458**；穿上品一套后 **atk≈24000 / hp≈67000 / def≈14000**，且**每升一级 ×1.4**。
裸装只 ×1.117/级。两者到 44 级差上百倍：玩家一击秒怪，而怪的破防原本写死成 `level*0.4`
（44 级才 17），打玩家 14000 防御只有 0.7% 伤害——**两头都不成立**。

所以怪的数值改为直接反推，且基准随装备一起涨，保证每个境界难度一致：

```
怪 hp  = 参考玩家每回合期望伤害 × 减伤系数 × 目标击杀回合数
怪 atk = 参考玩家血量 / 目标存活回合数 / 减伤系数 / 怪的技能倍率
```

普通怪锚定「上品一套」、精英锚定「极品」、boss 锚定「仙品」。
完整伤害管线：`((atk + 破防×0.28 + 速度×0.2 + 气运×0.1) × 技能倍率) × 100/(100+有效防御) × 暴击期望`，
有效防御再按 `pen/(pen+500)` 破防（上限无视 80%）。

**踩过的坑：防御不能跟着攻击等比放大。** 减伤是 `100/(100+def)` 的百分比模型，
`def` 一旦随攻击一起涨，减伤趋近 0、玩家 dps 反而退化成常数
（实测 25→36 级 hp 只涨 1.7 倍而攻击涨一万倍）。防御必须取常量级：
`effDef≈233`（减伤约 30%）÷ 破防上限 80% → `def = 1165`。

实测（`scripts/verify-high-realm-combat.ts`，25 项全 PASS）：

```
化神25 普通 上品一套 | 打死怪 4.0 回合 / 自己撑 33.7 回合
化神28 精英 极品一套 | 打死怪 10.0 回合 / 自己撑 21.4 回合
化神28 boss  仙品一套 | 打死怪 15.0 回合 / 自己撑 19.6 回合
（化神 ~ 合体 25-36 级同上，稳定命中 4 / 10 / 15）
```

### 已知上限：37 级起怪打不动满装玩家

`monsters` 的 hp/attack/defense 是 **integer（int32，上限 2147483647）**。
而「怪要打穿玩家防御所需的攻击」≈ 玩家血量 × 玩家防御 = `1.4^境界` 的**平方**，
约 **36~37 级起就捅破 int32**，只能截断：

```
大乘40 撑 326~509 回合      渡劫44 撑 13668~21254 回合   ← 怪已无威胁
```

这是 `stage_mult = 1.4^境界` + int32 的固有上限，不是配错数值。
真要解决需把列改成 **bigint** 或下调 `STAGE_STEP`（`equipment-instance-service.ts`），本次未动。

段间战力递增 ×1.56~2.34（每段都强于上一段，跨度均匀）。
修为定位：一只怪 ≈ 同级修为丹的 1/8。练气升一级约 50 只怪，元婴约 600 只——
**低境界打怪为主，高境界主力转洞府**（洞府固定 20 小时一级）。
精英 ×1.6、boss ×2.5（经验），boss 刷新 15 分钟。

**掉落/装备/配方必须成套，缺一个就是断链。**

| 环节 | 内容 |
|---|---|
| 掉落 | 200 只怪全部有 drops，0 只引用不存在的材料 |
| 材料 | 5 段 × 4（玄铁/灵晶 炼器，灵草/妖丹 炼丹） |

闭环：打怪 → 掉材料 → 炼器/炼丹 → 装备/丹药 → 打得动更高段的怪。

**两个命名坑（踩过）**：
- 靴子的 `itemType` 是 **`shoes`**，不是 `boots`
- 材料的 `itemType` 是 **`material`**，没有 `smithing_material` / `alchemy_material`
  这种类型。我第一版就是自己造了后两个，炼器/炼丹页按 item_type 取材料会全部落空。

**配方表没有 Drizzle 模型**（`smithing_recipes` / `alchemy_recipes` 不在 `schema.ts`），

**传送链是双向互指的**：传送门解析不靠 `portal_A_to_B` 的命名，而是靠
tile 上的 `portalTargetMapId` / `portalTargetPortalId` 字段（`map-portal.ts:109`）。
所以每加一张图，都要在**对侧**补一个回程阵，否则玩家进去就出不来了——

## 数值模型：为什么必须压缩品质倍率

需求给了两条硬规则（筑基初期 = 13、中期 = 14）：

```
A. 筑基中期下品 > 筑基初期上品
B. 筑基中期上品 > 筑基初期神话
```

这两条**数学上要求「每阶增幅」>「品级倍率差」**。装备生成时用的品质倍率是
0.7 / 1 / 1.7 / 2.6 / 3.8（上品/下品 = 2.43 倍），若每阶也按 2.5 倍递增，
从练气一层到元婴末期要乘 2.5^43，**直接溢出 int**。

所以把生效的品质倍率压缩到 **0.85 / 1 / 1.12 / 1.25 / 1.4 / 1.55（鸿蒙）**，
阶段步长取 **1.4**。验证结果：

```
[PASS] 规则A —— 675 > 635     （余量 6%）
[PASS] 规则B —— 889 > 794     （余量 12%）
[PASS] 规则C 结丹初期下品 > 筑基圆满上品 —— 1851 > 1742
[PASS] 同境界内品级单调递增 —— 482 < 567 < 635 < 709 < 794
[PASS] 数值不溢出 int（元婴末期神话）—— 26,892,648
```

**代价要说清楚**：品级对基础值的影响变小了（仙品只比凡品高 65%）。
品级的价值转移到**词条**上（凡品~上品根本没有词条）——这是有意的取舍，
不是没做。若以后想让品级在基础值上拉开，就必须放弃 A/B 两条规则。

**其余验证**：上品 0 条词条 / 极品 1 条 / 仙品 2 条；同词条仙品 > 极品
（attack 317→508）；三类都能掷出；剑修池不出格挡率；专精经验 0→56；实例落库。

**已知缺口**：炼器专精目前**没有 UI 展示**（等级/经验在库里，玩家看不见）。
打造行为会正常涨经验，但要让玩家感知到得在炼器页加一块展示。

### 逆天改命改造纪要（2026-10-18）

按需求做了三件事：**刷新一次、按构筑分池、重复承接转精进**。
`reversal-service.ts` 重写，`scripts/verify-reversal.ts` 实测三项全过。

**1. 每次逆天改命给一次刷新**。新增 `POST /api/game/breakthrough/reversal/reroll`，
限制落在服务端：新表 `player_reversal_rerolls` + **UNIQUE**(player_id, realm_linear)，
`onConflictDoNothing` 抢不到插入位就拒绝——前端按钮只是引导，刷库才作数。
已领取过本境界天机的不允许再刷（天机已定）。
**踩坑**：第一版建的是普通 INDEX，`onConflictDoNothing` 对非唯一索引不生效，
二次刷新照样通过——改成 UNIQUE INDEX 才拦住。

**2. 分池跟随构筑递进**。`fortunes` 表加 `category` 列，47 条可用气运逐条分池：

```
general 6（破境灵感/天命弘愿等真通用的）
combat 12（斗战）    longevity 12（长生）
sword 4  body 5  pill 3  talisman 5（流派）
```

抽取规则：**选了流派 → general + 流派池；只选道途 → general + 道途池；都没选 → 纯通用池**。
通用池永远在池中，保证任何构筑都凑得满三道。分类是人工按描述逐条定的
（比如「剑心通明」虽然名字带剑但效果是战斗修为，归 combat 不归 sword）。

**3. 重复承接 → 精进**。原先 roll 会排除已拥有的永久气运，池子小、后期好词条
全拿光之后候选越来越差。现在允许已拥有的天机再次现身（标记「已得 · 可精进」），
再承接时**不重复授予**，而是调 `appendFortuneAttrBonus` 在原账上追加属性：
blue +30% / purple +40% / gold +50% / red +60%。追加的 delta 记到已有那条
`playerFortunes` 的 ledger 上，将来到期/移除回滚时精进的部分一起算对。

**踩坑**：属性体系是整数记账，`attack +2 × 0.3 = 0.6` 被取整成 0 → 零 delta →
整个精进静默失效（账目都没记）。改成**非零项不足 1 的给 ±1 保底**。

**验证**（测试号实跑，跑完清理）：

```
[PASS] 分池 —— 抽 3 条全部在 general+sword 池内
[PASS] 刷新 —— 第一次成功，第二次「此番天机已刷新过一次」
[PASS] 精进 —— 攻击 +1 破甲 +1（blue 0.3 保底后），账目 1 笔
```

**注意**：精进数值上限没设——同一词条理论上可被反复精进。
每个大境界只发一次天机，频率可控，但若后期境界膨胀再考虑加衰减。

### 天赋落地纪要（2026-10-18）

**复核推翻了我原先"天赋没有节点"的说法。** 天赋其实是有的，问题是：

1. **只有两层，元婴之后是空的**：道途（筑基 major 2）→ 流派（结丹 major 3）→ **没了**。
   玩家结丹选完流派，一直练到满级都不再有任何选择。
2. **选完就看不见**：全项目只有洞府页那一个弹窗，选完即关，没有任何常驻展示，
   玩家在任何界面都看不到自己的天赋是什么。

**本次改动**（节点 6 → 14：2 道途 + 4 流派 + 8 道心）：

| 流派 | 纯强化 | 带代价的偏锋 |
|---|---|---|
| 剑修 | 剑心通明（攻+7 破甲+5 招式+3） | 剑走偏锋（攻+11 速+6 **气血-5**） |
| 体修 | 不动明王（血+7 防+5 格挡+3） | 血战十式（攻+7 血+5 **防御-4**） |
| 丹修 | 医者仁心（血+6 法+5 减伤+3） | 毒手药王（攻+6 法+5 法宝+4） |
| 符修 | 符阵宗师（法+7 法宝+6） | 御符如臂（速+5 法+5 法宝+3） |

每个流派都给两条，一条纯强化、一条**用负面属性换更高正面收益**，
这样元婴这次抉择才有取舍，而不是"选大的那个"。

**为什么不用改表**：`player_talents` 的 `(player_id, kind)` 唯一索引天然就是"每层各一行"，
而 `kind` 是 text 字段，加一个 `daoxin` 即可 —— 不需要 migration，也不用动索引。

**顺手修的两个 bug：**

1. 前端弹窗标题/说明/按钮全是两层硬编码（`kind === "direction" ? "道途抉择" : "流派抉择"`），
   第三层会显示成"流派抉择"。已改成三层映射。
2. **负值显示成 `+-5%`**：原写法是 `+{Math.round(v*100)}%`，
   带代价的道心有负数值，会渲染出「气血 +-5%」。已修，并给负值加了红色区分。

**数值护栏**：8 个道心净收益 0.08-0.15，全在 ±15% 内；
符修系（符修 + 两个道心）全程未给 `spiritualSense`。

**部署要点**：改的是服务端 + 前端，需要
`next build` → 把 `.next/standalone/server.mjs` 同步到根目录（服务跑的是根目录那份，
直接 build 不会生效）→ `systemctl restart immortality-web`。
**game-server 没重启**：它的天赋逻辑未改、数据从库读，重启会踢掉在线玩家。

**顺带补齐的另一半**：选完之后看不到自己天赋的问题也一并解决了。新增角色页「道途」卡片
（`talent-panel.tsx` + `/api/game/talent/mine` + `getPlayerTalentOverview`），
三层按顺序列出已选节点（名称/描述/当前境界实际生效的加成）+ 合计；
未选的层显示"未定 —— 入洞府可抉择"或"未至 —— 元婴后方可抉择"。
一个都没选时整块不渲染，避免角色页出现空卡。

验证方式（因为 `player_talents` 是 0 条、没人选过天赋）：临时借一个号写入三层记录，
确认总览输出与排序正确后立即删除 —— 结果是三层顺序 `direction → path → daoxin` 正确，
各节点在元婴(major 4)的加成与设计值逐一吻合（剑走偏锋 `attack +0.11 / speed +0.06 / maxHp -0.05`），
测试数据已清理，`player_talents` 回到 0 条。

**注意**：展示页现在对所有人都是不显示的 —— 因为还没有任何玩家作过抉择。
等有人升到筑基作出第一次抉择后，卡片才会出现。这不是 bug。

### 落地纪要（踩过的坑，后面几个子任务照着避）

1. **`alchemy_recipes` 不在 drizzle schema 里**——由炼丹服务用 raw SQL 动态建表，
   插入只能用 raw SQL，并沿用服务端的 `WHERE NOT EXISTS (recipe_code)` 去重写法，
   否则会和离线包同步逻辑互相覆盖。
2. **id 前缀必须前后一致**：材料脚本按 `lq/zj/jd/yy` 生成 id，
   丹药脚本里手写引用时写成了 `lianqi`，导致 7 条丹方指向不存在的材料。
   → 每个子任务写完都要跑"引用目标是否存在"校验。
3. **装备效果键是联合类型**，不是 string；生成脚本要取 `items.$inferInsert["effects"]` 的类型。
4. 材料**追加**进怪物 `drops`（读旧值再 push），不能覆盖——已验证原掉落完整保留。
5. 种子类材料刻意不挂掉落（走种植线与商铺），校验时要排除，否则会误判为"无获取途径"。
6. **怪物数值字段全是 integer**：`skill_damage_bonus` 我一开始填了 `0.08`，直接插入失败
   （且报错被 drizzle 的冗长 query 日志淹没，要往上翻才看得见真正的错误）。
   百分比就填整数，别填小数。
7. **技能没有 `heal` 效果键**，治疗走 `regen`；效果键总共只有 11 种
   （defDown / speedDown / defUp / regen / stun / atkDown / shield / atkUp / burn / poison / freeze）。
8. 放怪前先确认「段 → 图」映射：柳渡集、青石里、太行山是**跨段通道图**，
   一张图里本来就有多段怪，新怪要按该图已有的段位放，不能按地图 min_realm 一刀切。
